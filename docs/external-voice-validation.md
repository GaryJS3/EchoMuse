# External voice validation

Baseline recorded on 2026-10-04, Windows, before editing. The working tree was
clean on branch `feature/external-voice-backend`.

The default Python lacked pytest. Tests used an isolated uv environment with
pytest, numpy, scipy, pyyaml, aiohttp and bcrypt; no repository dependency files
were changed. Without UTF-8, the first run had 1655 passed, 39 skipped and
54 failures, predominantly Windows source-file decoding errors.

Reproducible baseline command, run from `controller/`:

```powershell
uv run --with pytest --with numpy --with scipy --with pyyaml --with aiohttp --with bcrypt python -X utf8 -m pytest tests/ -q --tb=short
node --test tests/*.test.mjs
```

UTF-8 baseline: **1706 passed, 39 skipped, 3 failed** (75.39 seconds).
JavaScript baseline: **26 passed**, no failures.

Existing failures:

- `test_arbiter.py::test_contest_grants_the_claim_heard_first`: Windows timer
  scheduling grants the earlier-arriving claim before the test's later claim.
- `test_endpoints.py::test_go_fixture_is_what_the_controller_writes`: checkout's
  fixture has CRLF; generated bytes end with LF.
- `test_oww_models.py::test_models_dir_sits_beside_db`: Unix absolute-path fixture
  resolves with a Windows drive prefix.

These unrelated implementations and fixtures are preserved.

## Automated result

After implementation and the device-script line-ending fix: **1765 passed, 39 skipped, 3 failed** (87.49 seconds).
The failure set matches the UTF-8 baseline above. JavaScript remains **26 passed**.
The final full run used the repository's pinned networking and numpy versions:

```powershell
uv run --with pytest --with numpy==2.3.5 --with scipy --with pyyaml --with aiohttp==3.14.3 --with bcrypt --with websockets==17.1 --with zeroconf==0.151.3 --with protobuf python -X utf8 -m pytest tests/ -q --tb=short -rs
```

Focused external-boundary/decoder tests pass, including real localhost WebSocket
authentication/ownership, session cancellation and stale replies, announcement
play/stop, limits, and the shipped controller orchestrator's state/music cleanup.
Real HTTP WAV passthrough and ffmpeg resampling tests pass. Extracted decoder
function text was compared with HEAD and matches exactly. New modules pass
pyflakes, and `git diff --check` passes.

The skips concern host tools/platform features (awk, a C compiler, busybox,
Linux socket options) and unavailable openwakeword model packages.

## Live controller and speaker validation

On 2026-10-04, a C# WebSocket/REST probe exercised the deployed controller and
one real Echo. The operator's microphone mute was preserved during automated
speaker tests. No backend connection was replaced during subsequent verification.

**20 live checks passed**, covering:

- ESPHome default, configuration switching and invalid-value rejection.
- Unauthenticated rejection, Bearer upgrade and versioned hello.
- One-client ownership, second-client rejection and ownership release.
- Unknown session and unknown announcement-device rejection.
- Announcement playback, completion, targeted stop and disconnect.
- Valid idle state after disconnect and HA connectivity throughout external mode.

A quiet 48 kHz WAV used the existing speaker path. The controller logged
`Playback complete (device-confirmed after 0.5s, est 1.5s)`. Longer playback was
stopped and then interrupted by backend disconnect. The deployment was restarted
and authenticated WebSocket availability and HA reconnection were verified.

The operator subsequently observed the unavailable cue with external mode and
no client, then reported a working external application connection. A read-only
verification found external mode selected, both Echos connected with HA still
connected, and a recent successful wake turn with 3.28 seconds of microphone
audio, 235172 decoded response bytes and 8.39 seconds total duration. This
supports an accepted wake/input/response/playback cycle; it does not establish
every acoustic or failure scenario below.

## Remaining physical checks

Use an unmuted Echo and the connected external backend:

1. Return a long response and barge in: old audio stops, old session is cancelled,
   a new session ID appears, and a late old response cannot resume playback.
2. Play normal HA media, then start an external voice turn; verify media
   preemption/restoration and normal HA entities remain usable.
3. Test button/mute cancellation and backend disconnect during listening,
   thinking and playback. Verify idle state and music restoration.
4. Select `esphome` temporarily and verify an acoustic HA Assist round trip,
   then restore the operator's selected backend.

Automated coverage establishes these protocol and controller cleanup semantics;
these additional acoustic checks remain unverified.
